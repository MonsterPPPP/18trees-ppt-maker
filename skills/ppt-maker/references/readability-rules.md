# 独立阅读版式细则

配合引擎（`guizang-ppt-skill`）的瑞士风模板使用。引擎管"长什么样好看"，这里管"发给别人能不能自己读懂"。

---

## 一、页码与页眉体例

每一页正文页必须有两处编号，且**编号一致**：

```html
<div class="chrome-min tight">
  <div class="l">07 — 战略转向</div>
  <div class="r">07 / 14</div>
</div>
```

- 左侧 `.l`：`两位数字 + " — " + 中文章名`。中文章名是**读者能懂的结论词**，不是英文 eyebrow。
- 右侧 `.r`：`NN / MM`。`MM` = 总页数，全 deck 完全一致（含封面页计 01）。
- P0 铁律：**全 deck 不允许出现英文 eyebrow**。

**目录页固定放第 2 页**（第 1 页是封面），列出正文页的编号 + 章名，两列排布。
封面与结语也各占一个编号，所以 `MM = 正文页数 + 3` 这一档要算准。

## 二、字号下限与字重阶梯

### 下限（业务信息，不可越线）

| 场景 | 桌面端（1440×900） | 移动端（390×844） |
|---|---|---|
| 正文 / 表格单元格 / 卡片说明 | `max(18px, .94vw)` | `max(16px, min(3.5vw, 6.2vh))` |
| 中型结论句 / 卡片标题 | `max(18px, 1.4vw)` | `max(16px, min(3.5vw, 6.2vh))` |
| 表头 / meta / 页码 / 页眉 | `max(15px, .82vw)` + `font-weight:600` | `max(13px, .82vw)` |
| 主标题 | `min(4vw, 7vh)` 起 | 同左（双约束） |
| 封面 / 结语大字 | `min(6.5vw, 11.4vh)` | 同左 |

**放不下怎么办**：删文案 → 拆成两页 → 换版式。**永远不许压字号**。
中文方块字视觉面积比英文大，同样字号显得更满，所以中文页宁可少写两句。

### 字重阶梯（越大越细，越小越粗）

| 字号区间 | 字重 | 场景 |
|---|---|---|
| ≥ 6vw | 200 | 封面大字、巨号数字 |
| 3–5.9vw | 200–300 | 页内主标题、大编号 |
| 1.8–2.9vw | 300–400 | 中型标题 |
| 16–20px | 400–500 | 正文、卡片说明 |
| ≤ 15px | 500–600 | 表头、页码、页眉 |

同一页内，字号小的元素字重**不低于**字号大的元素。

### 双约束

所有大字用 `font-size:min(Xvw, Yvh)`，`Y ≥ X × 1.6`，否则 16:9 屏会被高度截断。
只用 `vw` 的大字在宽屏上必然溢出。

## 三、一页一个结构

**判定**：这一页除了标题区，主体是**一个**结构，还是两块互不相干的结构叠着？

合格：

- 一张表格（表头 + N 行）
- 一个统一网格（N 行 × M 列，每格同构）
- 一个流程条
- 一组同构卡片 + 一条**全宽的**收束条

不合格（都是被骂过的形态）：

- 上面时间线 + 下面一排小卡片
- 主体网格 + 底部一条 `border-top` 的说明小字
- 左栏一套体系 + 右栏另一套体系，两边条目不呼应

**收束条 vs 孤立小字**的区别：

| | 收束条（可以） | 孤立小字（不可以） |
|---|---|---|
| 位置 | 表格/网格的正下方，全宽 | 页面最底部，细线之上 |
| 内容 | 整页的总结论（"当前结论：……"） | 补充说明、口径备注、免责声明 |
| 视觉 | 有底色（accent 或浅灰），是张卡片 | 只有一条 `border-top` + 小字 |
| 读者感受 | "这是这页的结论" | "这行字是干嘛的？" |

不确定就按这个测：**把这行删掉，这页的信息完整吗？** 完整 → 它是孤立小字，删。

## 四、列表型内容一律上表

出现三个以上**同构项**（同维度对比、同阶段推进、同类别列举），就用表格或带分隔线的清单：

- **对比型**（旧模式 vs 新路径、方案 A vs B、矛盾维度罗列）→ 表头 + 行
- **推进型**（阶段、路线、时间线）→ 阶段 | 做了什么 | 得到什么 | 沉淀了什么
- **论证型**（论点 + 证据 + 影响）→ 结论 | 证据 | 为什么重要

表格样式基准：

```html
<div style="overflow:hidden;border:1px solid var(--border-subtle)">
  <table style="width:100%;border-collapse:collapse;font-family:var(--sans),var(--sans-zh)">
    <thead><tr style="background:var(--accent);color:#fff">
      <th style="padding:.9vh 1vw;text-align:left;font-size:max(15px,.82vw);font-weight:600;width:18%">列名</th>
    </tr></thead>
    <tbody>
      <tr style="background:#fff">…</tr>
      <tr style="background:var(--grey-1)">…</tr>   <!-- 隔行浅灰 -->
    </tbody>
  </table>
</div>
```

- 表头：accent 底 + 白字 + 加粗
- 行：`#fff` / `var(--grey-1)` 交替
- 单元格：`border-bottom:1px solid var(--border-subtle)`
- 第一列可以用 accent 色 + 加粗作为行标签
- **保持直角、无圆角、无阴影**

## 五、不许留大块空白

主体必须撑满内容区。出现空白通常是这三个原因：

1. **靠 `margin-top` 硬撑**：把 `margin-top:4vh` 收成 `2vh`，再用网格分配高度。
2. **`flex` 没有分配**：容器改成 `display:grid;grid-template-rows:1fr 1fr 1fr auto`，
   每块分到 `1fr`，最后一条 `auto`。
3. **内容太少**：从大纲第二部分的叙事文本里**多搬细节进来**（委托人明确要求过
   "从叙事文本中再多放一点东西进来，罗列的更多、更清晰"）。

## 六、对齐与整齐

- 两列/多列对照：**条目数对齐、句长对齐**。一列 4 条一列 6 条就是"排布不够整齐"。
- 长句拆成平行短项，让两列视觉重量接近。
- 同一类元素用同一套行内结构（`padding` 一致、`border-bottom` 一致、`gap` 一致）。
- 多列卡片的编号、图标、标题、描述四件套位置固定，不要一行一个摆法。

---

## 七、颜色

- 一份 deck **只有一个强调色**（默认 IKB 克莱因蓝 `--accent`）。
- 同层级元素统一底色（优先 `card-fill` 浅灰）；
  需要突出时**只允许一张**换成 `card-accent`，且必须真的值得突出。
- 禁：渐变、阴影、圆角、多彩拼贴。
- 深色页上强调字用提亮版（`--accent-bright`），不要用本色 accent（蓝压蓝看不见）。

---

## 八、移动端不许藏内容

移动端溢出**只能**靠重排解决（左右分屏改上下堆叠、字号用双约束、卡片换列数）。
**禁止**用 `display:none` 把正文藏起来 —— 那等于把 PPT 变成残页，
委托人已经否掉过一次这种做法。

---

## 九、逐页自检口诀

生成完每一页，问自己六句：

1. 这页底部的最后一行，删了会不会丢信息？（会丢 → 合并；不丢 → 删）
2. 有没有哪个词需要我开口解释？（有 → 改成中文结论或加解释）
3. 最小的字，离屏幕一臂远看得清吗？（看不清 → 删文案 / 换版式）
4. 主体是不是一个结构？（不是 → 收敛成一个）
5. 有没有成片的空？（有 → 网格分高度 + 补细节）
6. 只看这一页，陌生人读懂了吗？（没有 → 重做这页的主标题与结论）

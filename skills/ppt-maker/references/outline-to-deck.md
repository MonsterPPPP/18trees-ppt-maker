# 素材 → 大纲 → 页面

委托人从不说"帮我写个大纲"，他说的是"防止你失忆，现在请你立刻整理一份文档出来，作为 PPT 大纲，
我们一起优化这个大纲"。所以大纲文档是**共同的施工图**，不是交付物附录。

---

## 一、动手前先把素材吃透

1. **读完所有素材**：文档、聊天记录、链接、旧 PPT。链接打不开就换手段（浏览器取正文），别跳过。
2. **列出你缺的信息**，分三档问：
   - **必答**：缺了没法动手（受众、场景、要证明什么）
   - **决定可信度**：数字、时间线、金额、合作方
   - **合规审慎**：涉及法律/资质/数据使用的表述
3. 一次问一屏以内，标好优先级，让他能一口气答完。他配合度很高，愿意逐条回答。

拿到答案后**先复述确认**，再动笔。事实错比排版丑严重得多。

---

## 二、大纲文档的固定结构

文件名：`xxx材料-vN.md`，N 递增，**旧版全部保留**。

```markdown
# <材料名> vN

> 使用场景：<谁、什么场合、多长时间>
> 文档日期：YYYY-MM-DD
> 文件结构：第一部分用于制作 PPT；第二部分用于统一叙事、准备口播和回答追问。
> 原则：PPT 只呈现结论与证据，完整论证不堆在页面上。

---

# 第一部分：PPT 大纲

## 制作规则
- 页数、每页信息模块数量上限
- 能否脱离口播独立阅读
- 讲述时长（含精简版）
- 时间不足时优先讲哪几页
- 优先用流程图/时间轴/数字/表格，避免连续大段文字

## 封面（不计页数）
标题 / 副标题 / 署名 / 视觉结构

## 第 1 页：<一句能当标题的结论>
### 标题
### 核心结论
### 上屏文案          ← 每块一个小标题 + 2-4 句，3-6 块
### 当前基础          ← 事实类的锚点（用 `code` 排成一行 chips）
### 视觉结构          ← 用什么版式承载

## 第 N 页：…

---

## 下一轮必须补齐的信息
（逐条列出，标明为什么需要）

---

# 第二部分：完整叙事文本
（论证、证据、口播素材、可能被追问的细节，全部放这里）
```

**硬规则**：

- 每页**只讲一个核心结论**，其余 3–6 个模块都是它的支撑。一页两个论点就是设计事故。
- 「上屏文案」写的是**页面上真会出现的话**，不是你想说的话。想说的话进第二部分。
- 「视觉结构」在写大纲时就要想清楚，别留到做 HTML 时临场决定。
- 迭代时**只加不减**。要重组就先把上一版的信息按条目列出，重组完逐条核对（委托人会因为丢东西发火）。

---

## 三、大纲 → 页面的映射

一个标准页面的信息模块，落到 HTML 就是这几块：

| 大纲里的部分 | 页面上的位置 |
|---|---|
| 页标题 | 页眉 `.l` 的编号 + 页内主标题 |
| 核心结论 | 主标题本身（结论就是标题） |
| 上屏文案（3-6 块） | **一个**表格 / 网格 / 流程 的 3-6 个单元 |
| 当前基础 | 表格最后一行，或主结构下方的全宽 chips 条 |
| 视觉结构 | `data-layout` 的选择 |

**信息模块 → 结构的对应**：

| 模块形态 | 用什么结构 |
|---|---|
| 多维对比（A vs B vs C） | 表格：一列一个维度 |
| 阶段推进 | 表格：阶段 \| 做了什么 \| 得到什么 \| 沉淀了什么 |
| 论点 + 证据 + 影响 | 表格：结论 \| 证据 \| 为什么重要 |
| 并列概念（3-4 个） | 同构卡片网格 + 一条全宽收束 |
| 三点递进（时间窗口型） | 三列 + 大编号 |
| 流程图 / 服务链路 | 横向流程条（箭头连接） |
| 收束（三条结论） | 分屏：左宣言 + 右三条 |

---

## 四、页数与叙事顺序

- 正文页 12 页左右是信息密度的甜点区；超过 16 页要重新分章。
- **顺序按读者的理解路径走，不按你的工作路径走**：
  先讲"是什么"（产品/方案），再讲"卖给谁"（首批客户）——
  委托人专门要求过把产品蓝图排到首批客户之前。
- 目录放第 2 页（封面之后）。
- 结尾页承担"收束 + 下一步"，不要再塞新论点。

---

## 五、措辞纪律

- 未落定数字 → 定性表述（"已有付费用户"而不是"付费用户 N 人"）。
- 必须出现的价格 → 标注"待验证假设 / 访谈锚点"，明说不代表已成交。
- 不出现真实人名 → 用角色（"创始人"）。
- 责任边界写死：AI 辅助、真人对关键判断负责。
- 合规相关：不宣称绝对安全、不宣称垄断，涉及资质与数据的表述按业务实质审慎写。
